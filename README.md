# Fundmf

A Flutter + Firebase portfolio tracker for admin-provisioned mutual fund investors.
Fundmf reads CAMS consolidated statements from Gmail, parses every transaction, and
values the portfolio against live AMFI NAVs.

Authentication and data stay in **Firebase** (Auth + Firestore). The statement
ingestion runs as a **Node.js/Express service on Render**, deployed from `server/`
and served at **https://fundmf.onrender.com**.

---

## 1. What it does

**Investor**
- Signs in with the email the admin provisioned (Firebase Auth, email/password).
- First login links the auth uid to the existing `users/{email}` profile.
- If no profile exists, or `isApproved` is false, a blocking *pending approval*
  screen is shown with support contact details.
- Dashboard: invested amount, current value, absolute + % P&L, interactive
  allocation donut, scheme-wise holdings.
- Transactions: chronological CAMS rows, search by transaction ID / scheme,
  purchase-redemption filters, date range, detail bottom sheet, CSV/PDF export.
- Profile: admin-owned fields, masked PAN toggle, client ID, support request email.

**Admin (`fundmfservices@gmail.com`)**
- Create/edit/delete client profiles (name, email, PAN, phone, approval).
- Searchable client directory with link status and live portfolio summary.
- Manual CAMS sync trigger (authenticated REST call to the Render service) plus an
  audit log of scheduled/manual runs.

## 3. Firestore schema

### `users/{email}`
Email is lower-cased and used as the document id so the admin can provision a
client before the investor ever signs in.

| Field | Type | Notes |
| --- | --- | --- |
| `email` | string | Must equal the document id |
| `fullName` | string | Set by admin |
| `pan` | string | `^[A-Z]{5}[0-9]{4}[A-Z]$`, uppercase |
| `phone` | string | 10-digit Indian mobile |
| `clientId` | string | `FMF-<year>-<base36>` generated on create |
| `isApproved` | bool | Gates dashboard access |
| `uid` | string | Empty until first login links the auth user |
| `createdAt` / `updatedAt` | timestamp | Server timestamps |
| `linkedAt` / `lastLoginAt` | timestamp | Written on claim |

### `transactions/{transactionId}`
Document id is the CAMS `Transaction_ID`, which makes ingestion idempotent.

| Field | Type | Notes |
| --- | --- | --- |
| `transactionId` | string | CAMS unique id (or deterministic fallback) |
| `pan` | string | Maps the row to a client |
| `uid` | string | Owning auth uid when the PAN is provisioned |
| `folioNumber` | string | |
| `schemeName` | string | |
| `schemeCode` | number | AMFI code, `0` when absent |
| `transactionDate` | timestamp | Used for ordering |
| `transactionType` | string | `Purchase`, `SIP`, `Redemption`, `Switch-In`, `Switch-Out`, `Other` |
| `amount` | number | Positive INR value |
| `units` | number | Positive units |
| `purchaseNav` | number | NAV at purchase |
| `sourceMessageId` | string | Gmail message id |
| `processedAt` | timestamp | Ingestion time |

Composite indexes: `pan ASC + transactionDate DESC` and `uid ASC + transactionDate DESC`.

### `sync_logs/{id}`
`status`, `trigger`, `messagesScanned`, `attachmentsParsed`, `transactionsCreated`,
`duplicatesSkipped`, `errors[]`, `errorMessage`, `durationMs`, `actor`,
`startedAt`, `finishedAt`.

## 4. Access control (`firestore.rules`)

- `isAdmin()` — signed in **and** (`email == fundmfservices@gmail.com` or custom
  claim `role == 'admin'`).
- `users/{email}`
  - read: admin, or the signed-in user whose token email matches the doc id.
  - create/delete: admin only, with PAN/email validation.
  - update: admin, **or** the owner updating only `uid`, `linkedAt`, `lastLoginAt`
    (the first-login link step).
- `transactions/{id}`
  - read: admin, or `resource.data.uid == request.auth.uid`, or the caller's own
    profile PAN equals `resource.data.pan` (single `get()` lookup).
  - write: admin only — the sync service writes with Firebase Admin credentials,
    which bypass these rules.
- `sync_logs`: admin only.
- Everything else: denied.

The `ux` on the client is not a security boundary: the admin panel is hidden from
investors *and* every write is rejected by these rules.

The HTTP endpoint has its own gate: `server/src/middleware/auth.ts` verifies the
Firebase ID token with the Admin SDK (`checkRevoked: true`) and only accepts the
admin email or a `role == 'admin'` custom claim. Anyone else gets `403`.

## 5. Financial engine

`PortfolioCalculator.calculate()` sorts transactions chronologically and keeps a
running average-cost balance per scheme:

- **Inflows** (`Purchase`, `SIP`, `Switch-In`): `units += units`, `cost += amount`.
  If a statement only carries units + NAV, `amount = units × NAV`.
- **Outflows** (`Redemption`, `Switch-Out`): units reduce, and principal is removed
  at the running average NAV (`units × avgCost`), clamped at the remaining cost.
- `Other` rows (STT, dividends) never change units or cost.

Outputs per spec: total invested (remaining cost basis), net active units, current
value (Σ units × latest NAV), absolute P&L, return %, and a scheme-wise breakdown
with average buy NAV, current NAV, allocation % and P&L. Schemes fully redeemed are
excluded from holdings and counted in `closedSchemes`. If MFAPI has no quote for a
scheme the app falls back to average cost and flags `navAvailable = false`.

Live NAVs come from `https://api.mfapi.in/mf/{schemeCode}` (latest entry first),
cached for 30 minutes with in-flight request deduplication.

## 6. Backend API (`server/`, Express on Render)

Endpoints:

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/health` | none | Render health check / uptime probe |
| `POST` | `/api/cams/sync` | `Authorization: Bearer <Firebase ID token>` (admin) | Run ingestion now and return the summary |

The pipeline (shared by the endpoint and the cron job, `services/cams-sync.ts`):

1. OAuth2 client from `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`,
   `GMAIL_REFRESH_TOKEN` (Render env vars).
2. Gmail query: `from:donotreply@camsonline.com has:attachment filename:csv is:unread`.
3. CSV parts are downloaded (inline data or attachment id).
4. Header row is detected among the first 60 lines, then column aliases are matched
   (`Transaction_ID`, `PAN`, `Folio_Number`, `Scheme_Name`, `Scheme_Code`,
   `Transaction_Date`, `Transaction_Type`, `Amount`, `Units`, `Purchase_NAV`).
5. PAN → `users` lookup resolves `uid`; the row is written to `transactions/{id}`
   only if that document does not exist (duplicates are counted, not overwritten).
6. The email is marked read and labelled `CAMS_PROCESSED` (label created on first
   run). Emails that cannot be parsed stay unread for inspection.
7. A `sync_logs` document records counts, errors and duration.
8. Only one sync runs per process; a concurrent trigger gets `409`.

Scheduling is a **Render cron job** (`render.yaml`, `npm run sync` →
`lib/scripts/run-sync.js`) that runs every 6 hours. It executes the pipeline
directly instead of calling the web service, so it does not depend on the service
being awake.

### Client configuration

The deployed backend is **https://fundmf.onrender.com** and it is the compiled-in
default (`AppConstants.apiBaseUrl`), so a plain `flutter build` targets production.
Point a local run at the dev server instead:

```sh
flutter build web                                                   # deployed backend
flutter run --dart-define=FUNDMF_API_BASE_URL=http://localhost:8080  # local backend
```

From an Android emulator the host machine is `http://10.0.2.2:8080`.
`AdminRepository` attaches the signed-in admin's Firebase ID token to each call and
maps HTTP failures to readable messages.

## 7. Setup

### Prerequisites
- Flutter 3.47+ / Dart 3.14 (analysed and unit-tested with Flutter 3.50.0)
- Firebase CLI, a Firebase project with **Authentication → Email/Password** enabled
- Node.js 20 for the backend
- A Render account (Web Service + Cron Job)
- Gmail API enabled on a Google Cloud project with an OAuth2 client

### App
```sh
flutter pub get
dash run flutterfire configure --project=<your-project-id>   # writes lib/firebase_options.dart
flutter run                       # talks to https://fundmf.onrender.com
flutter run --dart-define=FUNDMF_API_BASE_URL=http://localhost:8080   # local backend
```
Create the admin account (`fundmfservices@gmail.com`) in Firebase Authentication →
Users, then create one `users/{email}` document per client (or use the admin panel).

### Security rules and indexes
```sh
firebase deploy --only firestore:rules,firestore:indexes
```

### Local backend
```sh
cd server
cp .env.example .env        # fill in the values below
npm install
npm run dev                 # tsx watch, http://localhost:8080
curl http://localhost:8080/health
```

### Render deployment
Use the included blueprint (`render.yaml`) or create the two services manually:

1. **Web Service** — name it `fundmf` (that is what makes the URL
   `https://fundmf.onrender.com`), root directory `server`, build
   `npm install && npm run build`, start `npm start`, health check path `/health`.
2. **Cron Job** — root directory `server`, schedule `0 */6 * * *` (UTC),
   build `npm install && npm run build`, command `npm run sync` (runs
   `lib/scripts/run-sync.js`).

Environment variables (both services need the Firebase and Gmail values):

| Variable | Notes |
| --- | --- |
| `FIREBASE_SERVICE_ACCOUNT` | Full service account JSON on one line (Secret) |
| `FIREBASE_PROJECT_ID` | Optional; taken from the service account otherwise |
| `GMAIL_CLIENT_ID` / `GMAIL_CLIENT_SECRET` / `GMAIL_REFRESH_TOKEN` | Secrets |
| `ADMIN_EMAIL` | Defaults to `fundmfservices@gmail.com` |
| `ALLOWED_ORIGINS` | Comma separated web origins, or `*` |
| `CAMS_MAX_MESSAGES` | Optional; unread CAMS emails scanned per run (default 25) |
| `PORT` | Render injects this automatically |

If you deploy without the blueprint, add `NODE_VERSION=20.18.0`. `GOOGLE_APPLICATION_CREDENTIALS`
pointing at a mounted service-account file also works instead of the JSON env var.

Finally point the app at the deployed URL with `--dart-define=FUNDMF_API_BASE_URL=...`.

### Gmail OAuth
1. Google Cloud Console → enable **Gmail API**.
2. OAuth consent screen → add scope `https://www.googleapis.com/auth/gmail.modify`.
3. Create an OAuth2 client (Desktop/Web) and generate a refresh token for
   `fundmfservices@gmail.com` with `access_type=offline` + `prompt=consent`.
4. Store the three values as Render environment variables (never in the repo).
5. Redeploy so the new values are picked up.

## 8. Data caveats

- CAMS statement layouts vary by registrar/period; the parser matches header
  aliases and skips preamble rows, but a new layout may need an added alias.
- Redemption principal uses the average-cost method, which may differ slightly from
  AMC-reported realised gains (FIFO).
- NAVs are end-of-day AMFI values, not intraday.
- Fundmf is a tracking tool, not investment advice.
